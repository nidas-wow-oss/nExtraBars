v2.2.2 (2026-04-12) - BUGFIX RELEASE COMPLETO
----------------------------------------------

BUGS ARREGLADOS:
----------------
1. Barra de mascota se desincronizaba cuando la pet recibía Fear/CC
2. Barra de mascota se bugeaba cuando el JUGADOR recibía Fear/CC
3. Desincronización total cuando jugador Y pet reciben Fear simultáneamente
4. Problemas con cualquier efecto de pérdida de control (Polymorph, Stun, etc.)


CAUSA RAÍZ DEL BUG:
-------------------
El addon tenía DOS sistemas separados escuchando eventos de mascota:

1. WATCHER en nExtraBars.lua:
   • Escuchaba PET_BAR_UPDATE, UNIT_PET, etc.
   • Solo llamaba RefreshAllLayout() para reposicionar frames
   • RefreshAllLayout() se saltaba durante combate (InCombatLockdown check)
   • NO actualizaba el contenido/estado de los botones

2. NEB_ABTFrame en NEB_ButtonTemplate.lua:
   • Sistema principal de actualización de botones
   • NO estaba registrado para eventos de mascota
   • NO estaba registrado para eventos de control del jugador
   • Resultado: botones nunca se actualizaban cuando había cambios de CC

PROBLEMA ESPECÍFICO CUANDO JUGADOR RECIBE FEAR:
------------------------------------------------
• Cuando el jugador recibe Fear, el juego está en combate
• Los eventos de mascota se disparan pero...
• RefreshAllLayout() se salta por InCombatLockdown()
• Los botones nunca se actualizan porque NEB_ABTFrame no escucha estos eventos
• La barra queda en estado inconsistente hasta que sales de combate


SOLUCIÓN IMPLEMENTADA:
----------------------
Archivo: NEB_ButtonTemplate.lua

1. EVENTOS DE MASCOTA AGREGADOS (líneas 42-44):
   ```lua
   NEB_ABTFrame:RegisterEvent("PET_BAR_UPDATE");
   NEB_ABTFrame:RegisterEvent("PET_BAR_UPDATE_COOLDOWN");
   NEB_ABTFrame:RegisterEvent("UNIT_PET");
   ```

2. EVENTOS DE CONTROL DEL JUGADOR AGREGADOS (líneas 45-47):
   ```lua
   NEB_ABTFrame:RegisterEvent("PLAYER_CONTROL_LOST");
   NEB_ABTFrame:RegisterEvent("PLAYER_CONTROL_GAINED");
   NEB_ABTFrame:RegisterEvent("UNIT_AURA");
   ```

3. MANEJO DE EVENTOS DE MASCOTA (después línea 129):
   ```lua
   elseif (event == "PET_BAR_UPDATE" or event == "UNIT_PET") then
       -- Actualizar todos los botones cuando la barra de mascota cambia
       for i,v in ipairs(self.buttons) do NEB_ABT_Update(v); end

   elseif (event == "PET_BAR_UPDATE_COOLDOWN") then
       -- Actualizar cooldowns cuando la barra de mascota se actualiza
       for i,v in ipairs(self.buttons) do NEB_ABT_UpdateCooldown(v); end
   ```

4. MANEJO DE EVENTOS DE CONTROL DEL JUGADOR (después línea 137):
   ```lua
   elseif (event == "PLAYER_CONTROL_LOST" or event == "PLAYER_CONTROL_GAINED") then
       -- Cuando el jugador pierde/gana control (Fear, Stun, etc.)
       for i,v in ipairs(self.buttons) do NEB_ABT_Update(v); end

   elseif (event == "UNIT_AURA") then
       -- Actualizar cuando player o pet reciben/pierden auras
       if (arg1 == "player" or arg1 == "pet") then
           for i,v in ipairs(self.buttons) do NEB_ABT_Update(v); end
       end
   ```

POR QUÉ FUNCIONA AHORA:
-----------------------

1. EVENTOS DE MASCOTA:
   • PET_BAR_UPDATE: Se dispara cuando la barra de pet cambia (Fear, dismiss, etc.)
   • UNIT_PET: Se dispara cuando ganas/pierdes pet o cambia de estado
   • PET_BAR_UPDATE_COOLDOWN: Para cooldowns específicos de pet

2. EVENTOS DE JUGADOR:
   • PLAYER_CONTROL_LOST: Cuando pierdes control (Fear, Stun, MC, etc.)
   • PLAYER_CONTROL_GAINED: Cuando recuperas control
   • UNIT_AURA (player/pet): Detecta CUALQUIER cambio de buff/debuff

3. ACTUALIZACIÓN INMEDIATA:
   • NEB_ABT_Update() NO tiene check de InCombatLockdown()
   • Las funciones que llama (UpdateTexture, UpdateCooldown, etc.) tampoco
   • Solo las funciones de CAMBIO de comandos (SetCommand) están bloqueadas
   • Esto significa que LEER y ACTUALIZAR UI funciona en combate
   • Solo MODIFICAR configuración de botones está bloqueado (correcto)
